# bench — chemcheck 평가 장치

숫자를 담아두는 곳이 아니라 숫자를 뽑는 장치다. A·B·C 가 착지하면 여기서 다시 돌린다.

```bash
python -m bench.run --engine oracle          # 장치 점검 (오늘 돌아간다)
python -m bench.run --engine hallucinating   # 구조식 아닌 그림에도 답하는 인식기
python -m bench.run --engine none            # 바닥값 - 전부 침묵해야 한다
python -m bench.run --engine real            # A 착지 후 진짜 숫자
```

## 리포트가 판정률부터 시작하는 이유

침묵하는 검사기는 만들기 쉽다. 항상 판정불가를 내면 오탐률 0% 짜리 완벽한 도구가
되고, 동시에 완전히 쓸모없다. `--engine none` 이 정확히 그 상태를 보여준다 —
판정률 0%, 오탐률 0%. 판정률을 첫 줄에 두지 않은 리포트는 스스로를 속인다.

## 두 팔로 재는 이유

| 팔 | 판정기 |
|---|---|
| `chemcheck` | `verdict.judge` — 신뢰도 게이트 + 엔진 합의 + 골격/입체 구분 |
| `baseline` | `baseline.naive_judge` — 보류 없음. 예측 하나를 참조 하나와 대조 |

둘은 **같은 인식 결과**를 본다 (인식기는 한 번만 돈다). 차이는 판정 규칙뿐이므로,
두 성적의 차이가 곧 chemcheck 이 부품 위에 얹은 것의 크기다.

## 라벨을 믿지 않는다

`validate` 가 각 케이스의 라벨을 PubChem + RDKit 으로 다시 계산해 대조한다.
(이름, 그려진 SMILES) 의 참 관계는 OCSR 없이 계산되기 때문이다. 선언과 계산이
어긋나면 도구가 아니라 케이스가 틀린 것이다.

라벨이 틀린 채로 잰 오탐률은 오탐률이 아니다.

## 알려진 한계

- **합성 코퍼스는 렌더러가 하나다.** `CORPUS` 의 그림은 전부 RDKit 이 그렸다.
  실제 슬라이드는 ChemDraw 내보내기·스크린샷·손그림이 섞이고 해상도도 제각각이다.
  여기서 나온 숫자는 OCSR 성능의 **상한**이지 현장 성능이 아니다.
- **`decks/` 가 비어 있다.** 현장 숫자는 라벨을 손으로 붙인 실제 강의자료에서 나온다.
  이게 채워지기 전까지 이 장치는 자기 자신만 검증한다.
- **케이스가 9건이다.** 비율을 말할 크기가 아니다. 지금은 장치가 도는지 보는 용도다.

## 실측 기록 1 — 실제 강의자료 (2026-09-09)

자료: 고분자 합성 메커니즘 강의 덱, 8장, PDF. Gemini Notebook 이 생성한 한국어 자료.
저작물이므로 저장소에 두지 않는다. 제자리에서 읽었다.

    그림 8건 중 0건을 판정했습니다  (판정률 0.0%)
      [판정불가]  8   그림 옆에 이름이 없음

판정률 0%. 이유가 셋이고 깊이가 다르다.

**1. 텍스트 레이어가 없다.** PDF 전체에 0자. pdfminer.six 와 pypdfium2 로 각각
독립 확인했으므로 우리 추출 경로의 버그가 아니다. 페이지가 5121x2880px 통짜
래스터다 - 이름이 픽셀 안에 있어 기계가 읽을 수 없다.

**2. '그림'이 슬라이드 전체다.** 추출된 이미지는 구조도가 아니라 슬라이드 한 장
통째다. OCSR 에 먹여도 제목·본문·여러 구조가 섞인 그림이라 의미가 없다.

**3. 구조가 일반식이다.** 3장은 디이소시아네이트(OCN-R-NCO) + 디올(HO-R'-OH)
-> 폴리우레탄이고, 6장은 라디칼 중합과 개환 중합의 반응 도식이다. R, R' 는
InChIKey 로 표현할 수 없고, 반응 도식은 단일 화합물이 아니다.

1 과 2 는 입력 형식 문제라 고칠 수 있다 (원본 PPTX, 또는 OCR + 구조 검출).
**3 은 다르다 - 이 자료에는 검사할 대상이 애초에 없다.** chemcheck 은 '한 장에
화합물 이름 하나와 그 구조 그림 하나'를 전제하는데, 이 덱은 반응 메커니즘과
개념 도해로 되어 있다.

덱 하나다. 일반화하면 안 된다. 다만 처음 만난 실제 자료가 전제에 맞지 않았다는
사실 자체가 정보다. 다음 자료는 **개별 화합물의 이름과 구조가 함께 나오는**
것이어야 이 장치가 잴 것이 생긴다 - 유기화학 강의자료가 그런 형태다.

곁들여: 이 덱은 AI 가 생성한 자료다. chemcheck 의 표적 그 자체인데,
평면 이미지라 chemcheck 이 보지 못한다.

## 실측 기록 2 — 그림의 대부분은 구조식이 아니다 (2026-09-09)

자료: 탄화수소 강의 덱, 398장 PPTX. 텍스트 100%, 그림과 글자가 함께 있는 장 167장.
형태는 chemcheck 의 전제에 맞는다. 그런데 그림 쪽이 다르다.

    그림 총계     371
    고유 그림     109      <- 304 건이 중복
    최다 반복      46 번    <- 구조식은 46 번 반복되지 않는다

표본 12개를 눈으로 확인했다. 화학 구조식은 2~3개뿐이었다. 나머지는 아인슈타인
캐리커처, 오비탈 도해, 비커 그림, 플라스틱 용기 사진, 소스병 사진, 검은 사각형.
`extract.py` 의 필터는 크기뿐이고 '이게 구조식인가'는 아무도 묻지 않는다.

**이것이 실제 자료의 지배적 오탐원일 수 있다.** OCSR 은 무엇을 주든 SMILES 를
낸다. 클립아트에서 읽은 SMILES 가 슬라이드의 이름과 다르면 '오류'가 되는데,
자료는 멀쩡하다.

그래서 `Truth.NOT_A_STRUCTURE` 를 넣고 `--engine hallucinating` 으로 재봤다.
구조식은 제대로 읽고 구조식이 아닌 그림에도 신뢰도 0.95 로 답하는 인식기다.

    [chemcheck]   오탐률 22.2% (2/9)   물러남 0.0% (0/3)
    [baseline]    오탐률 33.3% (3/9)   물러남 0.0% (0/3)

**인식기 하나로는 chemcheck 의 방어가 버티지 못한다.** 신뢰도 게이트(0.80)는
0.95 를 통과시키고, 합의 게이트는 엔진이 하나면 언제나 합의한다. 보류 규칙이
오탐을 3건에서 2건으로 줄였을 뿐이다.

이것이 다중 엔진 합의가 선택이 아니라 필수인 이유다. 엔진이 둘이고 서로 다른
답을 내면 그때 비로소 보류된다. **A 가 두 인식기를 함께 세우는 일은 정확도
문제가 아니라 오탐 문제였다.**

### 판정률의 분모를 바꿨다

구조식이 아닌 그림에 물러난 것은 잘한 일이지 못 본 것이 아니다. 그것을 분모에
넣으면 옳게 행동한 데 벌점을 매기게 된다. 판정률의 분모는 이제 '판정했어야 할
케이스'다. 대신 분모를 우리가 정하게 되므로 조작 여지가 생긴다 -
`NOT_A_STRUCTURE` 라벨은 사람이 눈으로 붙이고, `validate` 가 근거(note) 없는
선언을 거부한다.

## 실측 기록 3 — 전제는 성립한다. 오탐이 날 자리도 나왔다 (2026-09-09)

탄화수소 강의 덱 398장을 인식기 없이 끝까지 돌렸다. 인식기가 없으므로 판정은
전부 보류지만, 보류 사유의 갈래가 전제를 재준다.

    전체 장                 398
    그림이 있는 장          167
    이름이 잡힌 장          296
    그림+이름 둘 다 있는 장 128     <- 판정 후보 장
    그 장들의 그림          279 건   <- 전체 371 건의 75%

    [판정불가] 371
           278  인식기를 쓸 수 없음    <- 이름은 잡혔다. A 만 오면 판정된다
            93  그림 옆에 이름이 없음  <- 전제가 안 맞는 장

**전제는 성립한다.** '슬라이드에는 이름과 그림이 함께 있다'가 실제 자료에서
그림 기준 75% 로 지켜졌다. 첫 자료(고분자 PDF)에서 0% 였던 것과 대비된다 -
그쪽은 텍스트 레이어가 없었다.

### 그런데 '이름이 잡혔다'가 '화합물 이름이 잡혔다'는 아니다

해석된 고유 이름 168종 중 상위:

    47 Alkenes    41 Benzene   22 Ethane     18 Ethyne    17 Platinum
    14 Sol        12 PSV       12 Palladium  9 Challenge  6 ene   6 Suffix

`Alkenes` 는 분류명이고 `Sol`·`PSV`·`Challenge`·`ene`·`Suffix` 는 화합물이
아니다. PubChem 은 분류명과 상표명을 정식으로 들고 있어서 해석해 준다
(`Challenge` 는 제초제 상표명, `Sol` 은 당의 동의어).

**판정 후보 장 128개 중 24개(그림 77건, 후보의 28%)는 잡힌 참조가 전부
분류명이거나 잡음이었다.** 대부분 `Alkenes` 하나뿐이다. 그 장들의 그림은 맞게
그려진 특정 알켄인데, 참조는 분류명이다. 인식기가 오면 여기서 '오류'가 난다 -
자료는 멀쩡한데.

그리고 후보 장 128개 중 77개는 **참조가 하나뿐이다.** '참조 3개 중 하나라도
맞으면 통과'라는 방어는 참조가 하나이고 그것이 틀렸을 때 아무것도 하지 못한다.

### 코퍼스에 반영한 것과 남긴 것

반영: 진짜 이름 옆에 분류명·잡음이 함께 있는 장 2건. 오라클로는 통과한다 -
참조 예산 안에 진짜 이름이 함께 들어오면 방어가 작동한다.

남긴 것: **진짜 이름이 아예 없고 분류명만 있는 장.** 이건 '그림이 틀렸다'가
아니라 '검사할 주장이 없다'에 가깝다. 슬라이드가 특정 화합물을 지목하지 않았는데
도구가 지목했다고 치고 대조하는 것이다. 라벨 체계를 하나 더 두어야 할 수도
있는데(구조식이 아님과 짝을 이루는 '주장이 없음'), 그 전에 이름 해석 쪽에서
분류명을 걸러내는 편이 옳은지 코디네이터·C 와 정할 일이다.
