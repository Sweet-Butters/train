# bench — chemcheck 평가 장치

숫자를 담아두는 곳이 아니라 숫자를 뽑는 장치다. A·B·C 가 착지하면 여기서 다시 돌린다.

```bash
python -m bench.run --engine oracle    # 인식기 없이 장치 점검 (오늘 돌아간다)
python -m bench.run --engine none      # 바닥값 - 전부 침묵해야 한다
python -m bench.run --engine real      # A 착지 후 진짜 숫자
```

## 리포트가 판정률부터 시작하는 이유

침묵하는 검사기는 만들기 쉽다. 항상 판정불가를 내면 오탐률 0% 짜리 완벽한 도구가
되고, 동시에 완전히 쓸모없다. `--engine none` 이 정확히 그 상태를 보여준다 —
판정률 0%, 오탐률 0%. 판정률을 첫 줄에 두지 않은 리포트는 스스로를 속인다.

## 두 팔로 재는 이유

| 팔 | 판정기 |
|---|---|
| `chemcheck` | `verdict.judge` — 신뢰도 게이트 + 엔진 합의 + 골격/입체 구분 |
| `baseline` | `baseline.naive_judge` — 보류 없음. 예측 하나를 참조 하나와 대조 |

둘은 **같은 인식 결과**를 본다 (인식기는 한 번만 돈다). 차이는 판정 규칙뿐이므로,
두 성적의 차이가 곧 chemcheck 이 부품 위에 얹은 것의 크기다.

## 라벨을 믿지 않는다

`validate` 가 각 케이스의 라벨을 PubChem + RDKit 으로 다시 계산해 대조한다.
(이름, 그려진 SMILES) 의 참 관계는 OCSR 없이 계산되기 때문이다. 선언과 계산이
어긋나면 도구가 아니라 케이스가 틀린 것이다.

라벨이 틀린 채로 잰 오탐률은 오탐률이 아니다.

## 알려진 한계

- **합성 코퍼스는 렌더러가 하나다.** `CORPUS` 의 그림은 전부 RDKit 이 그렸다.
  실제 슬라이드는 ChemDraw 내보내기·스크린샷·손그림이 섞이고 해상도도 제각각이다.
  여기서 나온 숫자는 OCSR 성능의 **상한**이지 현장 성능이 아니다.
- **`decks/` 가 비어 있다.** 현장 숫자는 라벨을 손으로 붙인 실제 강의자료에서 나온다.
  이게 채워지기 전까지 이 장치는 자기 자신만 검증한다.
- **케이스가 9건이다.** 비율을 말할 크기가 아니다. 지금은 장치가 도는지 보는 용도다.
