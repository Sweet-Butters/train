LLM 이 그린 화학구조, 믿어도 될까요?

이름을 대면 정본이 곧바로 뜨고, 이미지를 주면 서버가 그림을 읽어 InChIKey 로 대조합니다. 맞는지 틀린지는 추론이 아니라 문자열 비교입니다.

오늘 실제로 잡은 오류

Gemini 가 그린 "카페인", 자기 캡션과도 안 맞았다

이름의 정본 InChIKey 는 RYYVLZVUVIJVGH. 그런데 서버가 이 그림에서 읽은 것은 CSXLFNRQOLIQAN — 골격부터 다르다. 카페인은 탄소 8 개인데 이 그림은 9 개로 그려져 있다. N9 에 메틸이 하나 더 붙어, 사실 그릴 수 없는 분자다. 그런데도 이미지 자신은 화학식을 "C8H10N4O2" 라고 적어 놨다 — 캡션과 그림이 서로 다른 말을 하고 있었다.

API

화면이 쓰는 것과 같은 엔드포인트입니다. 그대로 붙여 코드에서 검사할 수 있습니다.

POST /api/check
Content-Type: multipart/form-data

  image: <file>
  name:  "Caffeine"

-> 200 application/json
{
  "verdict":   "match" | "mismatch" | "unreadable",
  "grade":     "strong" | "weak" | null,
  "reference": {"name","smiles","inchikey","formula"},
  "read":      {"smiles","inchikey","heavy_formula","engines":[...]},
  "reasons":   ["골격이 다릅니다 (...)", "중원자 조성 ..."]
}

무료 · 오픈소스

  • 인식기 둘(합의 판정)을 그대로 씁니다
  • 3GB 급 모델이 필요합니다
  • 그림까지 가장 확실하게 검사하는 경로입니다

로드맵

  • 인식기서버에 두 번째 인식기(MolScribe)를 다시 올려 합의 판정을 복원한다 - 지금은 DECIMER 하나뿐이다.
  • 판정입체화학까지 본다 - 지금은 InChIKey 앞 14자(골격)만 비교한다.
  • 이미지슬라이드 한 장에 구조가 여럿일 때 자동으로 나눠 보내는 분할기.
  • 검증90장 평가 코퍼스로 판정 정확도를 잰다.
